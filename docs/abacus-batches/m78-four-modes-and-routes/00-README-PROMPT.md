## THE TWO QUIZ MODES — one core, two packs

Brain Brawl and Who Scene It are the same game with different prompts, so
`QuizCore` is written once and each mode is a content pack plus a config. Same
call that made `RallyCore` serve tennis and volleyball.

`node --experimental-strip-types tests/quiz_test.ts` → **36 passed**

Two details the tests pin down:

- **Options are shuffled, not just questions.** Otherwise the correct answer
  sits wherever the author wrote it and players learn the *position* instead of
  the material. There's a test asserting the answer doesn't always land in the
  same slot.
- **A wrong answer never scores negative.** A party mode that punishes falling
  behind hard enough makes the loser stop playing.

### Who Scene It — and how it avoids an IP problem entirely

The obvious version of a scene-recall game is stills from films, posters,
actors. This project cannot ship that: it needs licences it doesn't have and
likeness rights it can't get.

So **the scenes you recall are FEL's own venues**, rendered live by the M73
system. `sceneVenueId` on each question names a venue and the mode rebuilds it
behind the answer buttons — the question *is* the scene.

That's a better game (it rewards playing the product), it reuses work already
built and verified, and every asset is procedurally generated by this codebase,
so the IP risk is zero rather than managed.

The host character is deliberately **not** spawned in this mode — a body
standing in front of the venue draws the eye to the wrong thing and gives the
answer away.

## ACTING — the fifth discipline finally has a surface

`acting` was the only one of the five Creator Card disciplines you could put on
a card and never actually do. M28 shipped `VoiceCapture.ts`; nothing played it.

`node --experimental-strip-types tests/acting_irl_test.ts` → **40 passed**
(shared with IRL)

**What it judges, and what it deliberately does not.** There is **no speech
recognition** — no transcription, no accent model. That needs a service this
project has no credentials for, and faking it would be worse than not having
it. It scores **delivery** from three signals any browser measures locally:

| Signal | Question |
|---|---|
| **Timing** | did you hit the cue |
| **Energy** | did loudness match what the line asks for |
| **Range** | did you vary it, or read it flat |

That's the part a performance game actually cares about — hitting a cue with
the right intensity reads as good acting far more than clean pronunciation does.

**Privacy:** audio is analysed on-device and never uploaded for scoring.
Nothing leaves unless the player explicitly saves a take to a card.

Design choices the tests hold:
- **A whisper is judged on its own scale.** 0.08 loudness is full marks for a
  whisper line and a failure on a shout line.
- **Skipping lines is not optimal** — coverage multiplies the average, so
  ducking the hard line costs you.
- Notes are specific (*"Came in late on the cue"*, *"Flat — vary the
  delivery"*), because "try harder" teaches nothing.

Scripts in `content/actingScenes.ts` are **entirely original** — sports-adjacent
dramatic beats in this product's own world. No film, show or franchise is
referenced or evoked; no character stands in for a real person.

## IRL — real jumps, honestly scoped

The iOS design assumed HealthKit. **The web has no HealthKit.** This reads
`DeviceMotionEvent` instead — available on mobile browsers after an explicit
permission prompt, and **not at all on desktop**.

The mode says so. A feature that silently does nothing on half the devices
looks broken; this one explains itself and asks for the permission from a user
gesture, which iOS requires.

**How a jump is measured:** free-fall detection, not acceleration integration.
A jump has an unmistakable signature — push-off spike, a sustained window near
0g while airborne, landing spike — and flight time gives height directly via
`h = g·t²/8`. Double-integrating noisy phone accelerometer data drifts badly
within a second; airborne time is directly measurable and robust.

**The anti-cheat falls out of the physics.** Flight time is rejected above
1.2 s as well as below 0.18 s: *a thrown phone free-falls beautifully* and
would otherwise register as a two-metre vertical. There's a test named exactly
that.

## HONEST LIMITS

- **The cores are proven; the modes are not.** 116 tests cover the arithmetic.
  The glue — Babylon, HUD, mic, motion — isn't type-checked against the Abacus
  source (same limit as M74–M77). Expect small signature corrections.
- **IRL is the least verifiable thing in this batch.** The jump maths is tested
  against synthetic traces I generated from the physics; it has never seen a
  real phone. Calibration against actual jumps is a required next step, and
  `FREEFALL_G` / `TAKEOFF_G` are the two constants most likely to move.
- **Acting scoring is delivery-only by design** — worth saying to players so
  the absence of word-accuracy reads as a choice rather than a bug.
- **Quiz packs are starter content** — 12 questions each. A shipping quiz mode
  wants several hundred, and that's an authoring job, not an engineering one.
